    Evidence standard¶

    “Shipped” below means the capability exists in the reviewed repository, with tests where cited. It does not by itself prove that a particular hosted tenant, connector, desktop client, or production deployment exposes and successfully runs that capability. “Integrated-partially” means usable pieces exist but the end-to-end join or user path is incomplete. “In-progress” is supported by an open Meridian item or deployment follow-up. “Planned” is a target, not a present capability. “Unverified” means this review did not find evidence strong enough to state it as fact.

    Recommended application framing¶

    Meridian is a project-continuity layer for research, built from modular services that retain project context. Academic search, code intelligence, a typed project evidence graph, local Outputs provenance, and manuscript tools exist, but the research workflow is composed from separate tools and the cross-service links are still being validated. The Catalyst pilot will test one bounded workflow and measure whether it reduces reconstruction after interruption while making missing or stale evidence visible for human review.

    If Adam confirms the personal account, distinguish it from the DNABERT trace: “I have used Meridian for project coordination and thesis DOCX work. Separately, a read-only rehearsal traced an existing DNABERT results figure from archived inputs into a manuscript include; that chain is not yet linked to a Meridian project or verified end to end.”

    Use the concrete thesis/DOCX example only if Adam confirms the personal account. Explicitly distinguish that verified personal DOCX use from the wider, not-yet-verified research-to-code-to-output-to-manuscript path.

    Claims to qualify or remove¶

    • “One complete/fully integrated research graph” or automatic linkage from every output to a project and manuscript claim.
    • An automated “what should we do next?” recommendation engine.
    • The DNABERT read-only figure trace as proof of a Meridian-linked end-to-end workflow.
    • A complete hosted Zotero/PDF/private-library workflow; automatic citation retrieval or bibliography syncing.
    • A live, dependable Overleaf path.
    • Tigris as production backup, remote sync, restore or replication.
    • An operational 8–10+ project-root fleet.
    • GPU/HPC provisioning, checkpoint guarantees, broad compute capacity or completed large-scale benchmarks.
    • Reliable fresh-member onboarding or resolution of all pending tenant provisions.
    • Meridian itself dispatching six agents, or measured throughput based only on worker-cap settings.
    • Market-wide time savings, customer adoption, institutional validation or pilot results before those are measured.

    The application draft is candid about many of these limits already. The main tightening needed is to keep the broad research workflow explicitly framed as a platform direction/pilot hypothesis, and to distinguish capabilities present in source from paths verified in the actual host and production environment.
